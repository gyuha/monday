# paseo를 포크하고, 신규 기능은 추가 패키지로 얹는다

핵심 요구는 "한 폴더에 여러 에이전트를 배치하고 함께 동작시키는 것"이다. paseo(Apache-2.0)에는 이미 다음 기능이 있다.
- 같은 cwd에 여러 에이전트 두기
- `create_agent` MCP로 부모-자식 에이전트 만들기
- 데몬과 원격 접속

그래서 Hermes(Python, 자체 LLM 루프)보다 paseo를 기반으로 삼는다. 메신저 게이트웨이는 Hermes의 설계만 참고해서 TypeScript로 다시 만든다.

paseo를 수정하지 않고 위에 별도 계층만 얹는 방식은 쓰지 않는다. paseo의 Agent profile은 호스트 전체에 하나뿐이고 시스템 프롬프트도 없다(`packages/protocol/src/agent-profile.ts`). 따라서 이 제품의 핵심인 "폴더에 미리 정의된 역할 팀"을 만들려면 서버를 고쳐야 한다.

포크 운영 원칙:
- upstream remote를 유지하고 주기적으로 병합한다.
- 서버 수정은 최소한으로 하고 격리한다.
- 메신저 봇과 관리자 웹은 새 패키지로 만든다.
- Electron(`packages/desktop`)처럼 쓰지 않는 패키지는 파일을 지우지 않는다. 루트 `workspaces`와 빌드에서만 뺀다. 파일을 지우면 upstream이 그 파일을 고칠 때마다 병합 충돌이 난다.
- "Paseo" 브랜드는 다른 이름으로 바꾼다.

## 검토한 대안
- **Hermes 기반**: 폴더, 다중 에이전트, 프로바이더 래핑 개념이 없다. paseo의 TypeScript 코드도 재사용할 수 없다.
- **paseo 위에 별도 계층**: 병합 비용은 0이지만 폴더별 역할 팀을 우회 구현으로만 만들 수 있다.
- **포크 후 자유 수정**: 상류 추적을 사실상 포기하게 된다.
- **새 프로젝트에 일부만 벤더링**: 내부 import가 줄줄이 따라와서 복사 범위가 불확실하다. 데몬, 저장, 인증도 다시 만들어야 한다.
