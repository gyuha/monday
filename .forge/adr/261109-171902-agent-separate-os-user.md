# 에이전트 프로세스는 데몬과 다른 OS 사용자로 실행한다

에이전트는 셸과 파일 도구를 자유롭게 쓴다. 에이전트가 데몬과 같은 OS 계정으로 실행되면 `~/.monday`에 있는 팀 구성과 다른 사람의 프로바이더 키를 읽고 고칠 수 있다. 그러면 [팀 구성 ADR](261109-163314-team-config-in-daemon-store.md)과 프로바이더 항목을 관리자가 지정한다는 원칙이 무력해진다.

그래서 데몬(설정과 키 보관)과 에이전트 프로세스를 서로 다른 OS 사용자로 분리한다.

## 결과
- 에이전트 OS 사용자는 **디렉토리마다 하나씩** 둔다(2026-11-09 추가 결정). 디렉토리를 등록하면 그 디렉토리 전용 OS 사용자를 만들고, 디렉토리 파일의 권한을 그 사용자에게 맞춘다. 이렇게 하면 프롬프트로 다른 디렉토리에 접근하려 해도 OS 파일 권한에서 막힌다. 그래서 디렉토리 접근 목록이 실제 경계가 된다. 컨테이너는 쓰지 않는다.
- 대가로 데몬은 OS 사용자를 만들고 파일 소유권을 바꾸기 위해 root(sudo) 권한이 필요하다. 이 부분은 플랫폼(macOS/Linux/Docker)마다 따로 구현해야 한다.
- 에이전트는 자기 프로세스에 주입된 프로바이더 자격증명(env, 로그인 폴더)은 볼 수 있다. 보호되는 것은 다른 프로바이더 항목의 자격증명과 데몬 설정이다.
- paseo는 에이전트를 데몬의 자식 프로세스로 띄운다. 그래서 다른 사용자로 실행하는 부분(sudo/setuid, 또는 별도 런처)은 서버를 수정해야 한다. 이는 서버 최소 수정 원칙의 허용된 예외다.
