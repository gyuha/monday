# 사용자와 권한은 데몬 앞의 게이트웨이가 맡고, 데몬은 단일 소유자로 둔다

다중 사용자 로그인, 디렉토리 접근 검사, 감사 로그는 새로 만드는 **게이트웨이** 서비스가 맡는다. 웹앱과 텔레그램/슬랙 봇은 모두 게이트웨이를 거쳐서 데몬에 접근한다. paseo 데몬은 localhost에서만 연결을 받고, 지금처럼 단일 소유자 전제로 둔다. 게이트웨이는 `@getpaseo/client`로 데몬에 붙는다.

권한을 데몬 안에 넣지 않은 이유는 다음과 같다. 데몬 안에 넣으면 `packages/server/src/server/session.ts`에서 처리하는 수십 종의 요청마다 권한 검사를 끼워 넣어야 한다. 그러면 서버 수정을 최소로 하겠다는 원칙([ADR-261109-152306](261109-152306-paseo-fork-additive-packages.md))이 무너진다.

## 결과
- 웹에 필요한 기능(대화 스트림, 터미널, 파일 등)은 게이트웨이가 다시 노출해야 한다. 즉 API가 두 벌이 된다.
- 데몬 호스트에서 데몬에 직접 붙으면(로컬 CLI 등) 권한 검사를 우회하게 된다. 따라서 데몬 호스트에 접근할 수 있는 사람은 관리자와 같은 수준으로 신뢰한다.
- 데몬 안에서 실행되는 에이전트들의 MCP 도구(`create_agent` 등)는 게이트웨이를 거치지 않는다. 이 도구들은 데몬 내부에서만 쓰이므로 문제가 없다.
